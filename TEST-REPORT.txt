UPDATE 2026-10-25 — DUPLICATE ORDER PROTECTION (idempotency key)
- Browser creates one random key per cart/details and re-uses it on retry; double-clicks are blocked while a request is in flight.
- Server stores the key in orders.idempotency_key (additive column + unique index; existing data untouched) and returns the SAME order (HTTP 200, duplicate:true) instead of creating a new one or taking stock again.
PASSED (isolated temp DB, synthetic data):
- Old database created by the previous code upgraded in place; old order kept; old-style requests without a key still work.
- Same key sent 3 times in a row: 1 order created (201), 2 replays (200), same order number, stock reduced once.
- 12 identical requests fired simultaneously: exactly 1 order and 1 stock deduction.
- Malformed key rejected with HTTP 400.
NOT COVERED: a customer who deliberately edits the cart/details and presses Buy again is a new order by design; the manual admin WhatsApp-order route has no key.
